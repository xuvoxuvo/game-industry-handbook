# 游戏行业知识手册

游戏行业里可以被引用的事实、口径与方法。一篇文章一个 HTML 文件，直接发布，没有构建步骤。

线上地址：`https://xuvoxuvo.github.io/game-industry-handbook/`

---

## 结构

```text
.
├── index.html                                  # 文章列表
├── articles/<slug>/index.html                   # 正文（单文件，样式与脚本内联）
├── 404.html
├── favicon.svg
└── WORKFLOW.md                                 # 新增文章的完整步骤
```

每个页面都是自包含的：CSS 和 JS 内联，没有外部依赖，可以单独发人、离线打开、A4 打印。

## 为什么不用框架

试过 Astro + Markdown 的生成方案，问题不在构建慢，而在**页面控制权**：

- 目录要显示「01 一条结论」这样的短标题，正文标题却要完整——生成器只能从同一个标题推两套文字，得额外加字段。
- 表格题注、案例卡、术语框这类组件，用 Markdown 语法表达就要写插件，插件写错就是版面错。
- 一篇文章就是一个阅读器（目录、进度、当前案例），它更像「一份文档」而不是「一个内容条目」。

结论：**内容量还在个位数时，直接写 HTML 比维护一套生成管线更省事**，也更接近你看到的那份原稿。等到有十几篇、需要统一改版时再引入生成器，那时迁移成本才划算。

新增一篇 = 复制 `articles/2026-mobile-game-metrics/index.html`，改正文与目录，再在 `index.html` 里加一行。

## 页面逻辑

- 左侧贴边目录（220px）：短标题锚点、当前章节高亮、已读状态；下方阅读百分比与进度条，滚动时显示当前案例
- 右侧 900px 正文：导语（标签 / 两行标题 / 导语 / 元信息 / 5 个指标卡 / 开篇提示）→ 9 个章节 → 参考资料与站点信息
- 移动端（≤ 980px）：目录变顶部胶囊导航，页面顶部出现 3px 阅读进度条

改目录文字时注意：`<a href="#s1" data-label="01 一条结论">01 一条结论</a>` —— `data-label` 决定左上角进度条旁的短标签。

## 部署

推送到 `main` 后由 `.github/workflows/pages.yml` 直接上传静态文件（没有构建步骤）。首次需要在仓库 **Settings → Pages → Source** 选 **GitHub Actions**。

## 写作约定

- 数据分三层：可核实硬数据 / 第三方监测 / 倒推估算，每处标明属于哪一层
- 时间敏感的数字带时点（「2026 年 11 月」）
- 查不到就写「查不到」，不用「业内普遍认为」代替
- 中文不改字距；数字用等宽并开启 `tabular-nums`

更细的规则见 [AGENTS.md](./AGENTS.md)。
